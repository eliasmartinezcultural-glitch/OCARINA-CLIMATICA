# LEY MUNDIAL TRONCAL · OCARINA CLIMÁTICA V2.0

**Estado:** rector del producto · **Aplicación:** V3.20 y futuras versiones

## 1. SERIEDAD
Este proyecto está pensado para ser serio, verificable y durable. Su contenido climático debe apoyarse prioritariamente en información oficial, científica, documental o local claramente identificada.

## 2. REALIDAD Y REPRESENTACIÓN
La representación debe ser fiel a la naturaleza de aquello que muestra. Observado, pronóstico, estimado, derivado, documental y memoria se mantienen diferenciados. Nunca se utiliza diseño para hacer parecer medido lo que no fue medido.

## 3. REFERENCIA 40 / 60
**40 % VISUAL · 60 % TEXTO.**

El 40 % visual comprende fotografía real con procedencia, ilustración identificada, mapas, diagramas, color, composición, visualización de datos y multimedia.

El 60 % textual comprende explicación, contexto, evidencia, método, fechas, fuentes, créditos, límites y memoria.

No es una medición matemática de cada pantalla. Es una regla editorial: mucha riqueza visual sin sacrificar profundidad informativa.

## 4. 100 % INTERACCIÓN SENCILLA
La experiencia debe ser intensamente interactiva pero extremadamente fácil de usar.

**MIRAR → TOCAR → LEER → EXPLORAR → VOLVER.**

No se requiere conocimiento tecnológico. Ninguna función esencial dependerá de hover obligatorio, gestos secretos o controles diminutos.

## 5. COMPLEJIDAD INVISIBLE
El sistema interno puede ser altamente sofisticado: validación, contratos, snapshots, trazabilidad, estados de calidad, ingestión, catálogos, metadatos, QA y automatizaciones.

Pero esa complejidad no debe trasladarse al usuario.

**MUCHO SISTEMA DETRÁS. MUCHÍSIMA SIMPLICIDAD DELANTE.**

## 6. DISEÑO
El diseño es parte del conocimiento.

La interfaz debe ser grande cuando el contenido lo necesite, colorida sin perder legibilidad, visual sin convertirse en decoración vacía, jerárquica, respirable, coherente y orientada al territorio.

**La imagen no es relleno. El texto no es relleno. Cada recurso cumple una función.**

## 7. REPRESENTACIÓN REAL
Fotografía, mapa, documento, gráfico, audio o video real deben conservar procedencia, fecha o período cuando sea relevante, localidad, autor/proveedor y condición de uso cuando corresponda.

Las ilustraciones deben identificarse como ilustraciones.

Una ilustración nunca podrá hacerse pasar por fotografía, observación o registro histórico.

## 8. FUENTES DENTRO DEL LUGAR
Las fuentes se ven dentro de Ocarina.

No se construirá una webgrafía como experiencia principal.

El usuario debe poder comprender una pieza sin abandonar el proyecto: fuente, tipo de evidencia, fecha, localidad, alcance, significado, límites y crédito.

## 9. MULTIDISPOSITIVO REAL
Ocarina se diseña desde el origen para **320 · 390 · 420 · 680 · tablet · notebook · desktop**.

No se trata de encoger desktop. Cada escala puede cambiar composición, densidad, navegación, tamaño de imagen y cantidad de información visible.

Las imágenes reales futuras deberán prepararse para diferentes dispositivos mediante variantes de resolución, tamaños adecuados y dirección artística cuando corresponda. ## 11. INTERACCIÓN UNIVERSAL
Toda función importante debe poder operarse mediante las modalidades razonables del dispositivo: toque, puntero y teclado cuando corresponda.

No se permite que el significado dependa solamente de hover, color o movimiento.

## 12. NORTE
Todo lo que se construya debe responder:

> **¿Esto ayuda a conocer, comprender, documentar, recordar o valorar el clima y el territorio de San Patricio del Chañar?**

Si no, queda fuera.

## 13. PROFUNDIDAD POR CAPAS
La interfaz pública debe ser corta.

La profundidad vive debajo:

**CAPA 1 · MIRAR**  
**CAPA 2 · TOCAR**  
**CAPA 3 · ENTENDER**  
**CAPA 4 · EVIDENCIA**  
**CAPA 5 · FUENTE Y MÉTODO**  
**CAPA 6 · ARCHIVO / DOCUMENTACIÓN**

Se entra rápido y se profundiza tanto como se quiera.

## 14. NO REGRESIÓN
Ninguna nueva versión puede sacrificar realidad, trazabilidad, fuentes, localidad, accesibilidad, simplicidad, rendimiento o representación honesta.

## 15. FÓRMULA TRONCAL

**40 % VISUAL**  
**60 % TEXTO**  
**100 % INTERACCIÓN SENCILLA**  
**100 % MULTIDISPOSITIVO**  
**100 % TRAZABILIDAD**

Y detrás:

**1000 % SISTEMA.**

Esta última expresión es una metáfora interna de arquitectura, no una métrica.

## 16. ESTADO
Esta ley pasa a ser el nuevo norte troncal de V3.20. Las capas anteriores se conservan cuando sean compatibles; las futuras deberán alinearse con esta ley.

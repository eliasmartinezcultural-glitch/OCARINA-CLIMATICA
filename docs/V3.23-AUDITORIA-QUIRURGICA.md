# V3.23 · Auditoría quirúrgica y reparación

Fecha: 2026-10-01

## Diagnóstico

La versión anterior tenía una contradicción entre la arquitectura declarada y la experiencia publicada: la central climática se inyectaba debajo de una portada heredada y de un universo visual duplicado.

También existía una fragilidad de datos: el ingestor AIC intentaba reconstruir la tabla mediante expresiones regulares sobre texto, mientras la fuente oficial publica una tabla estructurada. El resultado observado era un snapshot de pronóstico vacío aunque AIC sí exponía valores para El Chañar.

## Reparaciones

1. La central 3.23 es la composición dominante de la pantalla Ahora.
2. La capa visual heredada 3.20 se elimina de la experiencia visible para evitar duplicación.
3. Cuatro puertas: Lluvia, Viento, Temperatura, Agua + tierra.
4. Estados de datos explícitos: observado, pronóstico, territorio, pendiente y sin dato.
5. El parser AIC ahora lee la tabla HTML por estructura.
6. La serie histórica SMN queda bloqueada hasta verificar una única identidad de estación.
7. Se elimina la ejecución programada duplicada de los ingestors específicos; la ingestión centralizada queda como ruta programada y las rutas específicas como ejecución manual.
8. Se agrega concurrencia para evitar dos procesos escribiendo snapshots al mismo tiempo.
9. El contrato histórico se alinea con 365 días.
10. QA específico para V3.23 y validación de snapshots.

## Regla de datos

Nunca transformar un pronóstico en observación. Nunca presentar otra localidad como San Patricio del Chañar. Nunca completar un vacío con una cifra inventada o vieja sin declarar su fecha y estado.

## Regla visual

La portada orienta. Las puertas profundizan. Los gráficos explican. Las fotografías prueban territorio. Ninguna pantalla debe competir con su propia navegación.

## Próxima fase

No agregar funciones horizontales. Profundizar verticalmente las cuatro puertas con gráficos, series verificadas, mapas/diagramas territoriales y fotografía local con procedencia.
